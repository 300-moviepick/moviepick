# 운영 임베딩 미생성 발견 → 일괄 생성 후 주제 인식

> 운영 DB에 영화 임베딩이 없어 의미 점수가 빠진 채 추천이 "정상처럼" 동작하던 것을 찾아내고, 일괄 생성으로 요청 주제를 인식하게 했습니다.

## 문제
운영에서 AI 추천은 오류 없이 영화 3편과 이유를 돌려줬습니다. 그런데 요청 문장의 주제와 관계없는 영화가 자주 나왔습니다.

## 원인
- 운영 DB에 영화 임베딩(`movie_embeddings`)이 만들어져 있지 않았습니다.
- 의미 점수 계산은 후보 영화마다 기본 0점에서 시작해, 현재 모델로 만든 임베딩이 있는 영화만 코사인 유사도로 점수를 올립니다. 대상 임베딩이 하나도 없으면 로그(`의미 검색 대상 임베딩이 없습니다.`)만 남기고 모든 의미 점수를 0으로 돌려줍니다(`AiMovieSemanticSimilarityService`).
- 의미 점수 결합 단계도 임베딩 기능이 꺼져 있거나 실패하면 기존 점수(리뷰 장르 선호)로 대체합니다(`AiHybridRankingScoreService`). 추천이 끊기지 않게 만든 장치라 오류가 겉으로 드러나지 않았습니다.
- 결과적으로 요청 문장의 의미는 빠지고 장르 선호 점수만으로 후보를 골랐습니다.

## 해결
- 앱 시작 시 한 번 실행되는 일괄 생성 기능(`AiMovieEmbeddingBulkSyncRunner`, `AiMovieEmbeddingBulkSyncService`)을 운영에서 켜고 전체 영화 임베딩을 만들었습니다. 설정 `movie.embedding.bulk-sync.enabled`로 켜며, 50편씩 최대 2,000편을 처리합니다.
- 완료 로그(`failed=0`)를 확인한 뒤 설정을 다시 껐습니다. 절차는 [DEPLOYMENT.md](../DEPLOYMENT.md)의 "운영 임베딩 일괄 생성"에 있습니다.

## 결과
- 운영 DB에 영화 임베딩 생성을 마쳤습니다(OpenAI text-embedding-3-small).
- "마블 영화 추천해줘" 요청에 더 마블스, 캡틴 마블, 썬더볼츠*가 추천되어 요청 주제를 인식하는 것을 확인했습니다.

## 배운 점
장애를 숨기는 대체 동작(fallback)은 서비스를 지켜 주지만 문제를 늦게 발견하게 만듭니다. 대체 동작이 일어났는지 로그로 확인하고, 배포 체크리스트에 데이터 준비 상태를 넣어야 합니다.
