# 성능 개선

## 측정 조건
- 도구: k6. 모든 수치는 **k6 50명 동시 요청 p95, 로컬 측정, 같은 측정자·같은 PC 전후 비교**입니다. 500명 수치는 같은 조건에서 동시 요청 수만 늘린 한계 측정입니다.
- 통과 기준: p95 < 500ms, 실패율 < 1%
- 데이터 규모: 회원 3만, 리뷰 10만, 리뷰 좋아요 20만, 게시글 5만, 게시글 좋아요 10만, 영화 2,000건
- 스크립트: `perf/k6/*.js`, 실행 `perf/run.sh`

## 개선 전후
| 대상 API | 방법 | 전 (p95) | 후 (p95) |
|---|---|---|---|
| `GET /api/movies/reviews?sort=likes` 리뷰 좋아요순 | 앞 5페이지 결과 캐시(TTL 3분) | 11,078ms | **11.13ms** |
| `GET /api/community/posts?sort=popular` 인기글 | 앞 5페이지 결과 캐시(TTL 3분), 검색어 없을 때만 | 7,477ms | **17ms** |
| `GET /api/admin/reports` 관리자 신고 목록 | N+1 제거(대상 글·리뷰를 IN 쿼리로 한 번에) + 상태·작성일 인덱스 | 84ms | **23ms** |
| 〃 500명 동시 요청 | 〃 | 2,245ms (미달) | **452ms** (통과) |

개선 후 500명 한계 측정: 리뷰 좋아요순 p95 44ms, 인기글 p95 45ms (두 API 모두 개선 전에는 50명에서 이미 미달이라 500명 측정을 생략했습니다).

## 개선별 내용

### 리뷰 좋아요순 — 결과 캐시
- 원인: 좋아요 수를 `review_likes`에서 세는 상관 하위 쿼리로 리뷰 10만 건을 정렬했습니다.
- 방법: 좋아요순일 때만 `ReviewListCacheService`의 `@Cacheable(sync = true)`로 page 0~4를 3분 캐시합니다.
- 자세히: [troubleshooting/01-review-likes-cache.md](troubleshooting/01-review-likes-cache.md)

### 커뮤니티 인기글 — 결과 캐시
- 원인: 게시글 5만 건 전체의 좋아요 수를 집계한 뒤 임시 테이블에서 정렬했습니다(EXPLAIN: Using temporary, Using filesort).
- 방법: 리뷰와 같은 캐시 방식(`PostListCacheService`). 다른 점은 **검색어가 없을 때만** 캐시하고, `Page` 대신 `PageResponse`로 바꿔 저장한다는 것입니다.

### 관리자 신고 목록 — N+1 제거 + 인덱스
- 원인: 신고마다 대상 글·댓글·리뷰를 따로 조회했고, 상태·작성일 정렬에 맞는 인덱스가 없었습니다.
- 방법: 대상을 종류별로 모아 IN 쿼리로 한 번에 조회하고(`AdminReportService`), 인덱스 `idx_report_status_created_at`, `idx_report_created_at`을 추가했습니다(`db/schema.sql`).

## 리팩토링 후 재측정 (성능 저하 없음 확인)
리팩토링 뒤 같은 리허설 시나리오를 다시 돌려 느려지지 않았는지 확인했습니다. 개선 전후 비교가 아니라 회귀 확인용입니다.

| 시나리오 | 리팩토링 전 | 리팩토링 후 | 판정 |
|---|---|---|---|
| 최근 개봉 영화 목록 50명 p95 | 32ms | 30ms | 저하 없음 |
| 랭킹 50명 p95 | 7ms | 5ms | 저하 없음 |
| 최근 개봉 영화 목록 500명 p95 | 1,402ms (미달) | 1,407ms (미달) | 같은 수준 |

## 남은 한계
- **캐시 범위**: 리뷰 좋아요순·인기글은 page 0~4만 캐시합니다. page 5부터와 캐시가 빈 첫 요청은 느린 쿼리를 그대로 탑니다.
- **TTL 지연**: 캐시를 지우는 코드가 없어 좋아요 수·순서가 최대 3분 늦게 반영됩니다.
- **최근 개봉 영화 목록**: 500명 동시 요청에서는 아직 기준을 넘습니다.
- **리뷰 작성**: 같은 영화에 대한 쓰기는 영화 행 잠금으로 줄을 섭니다([troubleshooting/03-write-deadlock.md](troubleshooting/03-write-deadlock.md)).
